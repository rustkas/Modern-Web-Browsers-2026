# Глава 7. WebNN (Web Neural Network) — ИИ в каждом браузере

В 2026 году выполнение нейросетевых моделей в браузере перестало быть экспериментом. WebNN (Web Neural Network API) — это стандарт W3C, предоставляющий веб-приложениям низкоуровневый доступ к аппаратным ускорителям машинного обучения: CPU, GPU и специализированным NPU/TPU .

В январе 2026 года спецификация WebNN достигла статуса Candidate Recommendation, а Chrome 146 открыл Origin Trial для тестирования API на реальных пользователях . Firefox также поддерживает WebNN через ONNX Runtime Web . Это означает, что браузерная платформа 2026 года готова к выполнению ИИ-нагрузок с производительностью, сравнимой с нативными приложениями.

Эта глава детально разбирает архитектуру WebNN, его модель работы с аппаратными ускорителями, форматы моделей и практические сценарии применения.

---

## 1. Использование NPU/TPU через стандарт WebNN API

WebNN — это API, спроектированный специально для **инференса** (выполнения уже обученных моделей), а не для обучения . Его задача — предоставить унифицированный, независимый от платформы интерфейс к ML-возможностям операционной системы и аппаратному обеспечению .

### 1.1. Модель программирования WebNN

WebNN следует двухэтапной модели :

**Этап 1: Построение вычислительного графа.** Разработчик использует `MLGraphBuilder` API для определения структуры модели: операции (слои), их входы, выходы и параметры (веса). Все операции строятся в виде графа, который затем компилируется в оптимизированный исполняемый граф .

```javascript
// Построение простого графа
const builder = new MLGraphBuilder(context);
const input = builder.input('input', { dataType: 'float32', dimensions: [1, 784] });
const weights = builder.constant({ dataType: 'float32', dimensions: [784, 128] }, weightData);
const bias = builder.constant({ dataType: 'float32', dimensions: [128] }, biasData);

const dense = builder.add(builder.matmul(input, weights), bias);
const output = builder.sigmoid(dense);
```

**Этап 2: Компиляция и выполнение.** Построенный граф компилируется в `MLGraph` — исполняемый объект, оптимизированный под конкретное аппаратное обеспечение . Затем разработчик передает входные данные и запускает выполнение:

```javascript
// Компиляция
const graph = await builder.build();

// Выполнение
const inputs = { 'input': inputTensor };
const outputs = await context.compute(graph, inputs);
```

### 1.2. Выбор аппаратного ускорителя

WebNN автоматически определяет доступные аппаратные ускорители и выбирает наиболее подходящий для выполнения модели. В 2026 году спецификация WebNN предоставляет механизм выбора устройств через `MLContext` :

```javascript
// Создание контекста с автоматическим выбором устройства
const context = await navigator.ml.createContext();

// Явный выбор устройства (экспериментально, в зависимости от реализации)
const context = await navigator.ml.createContext({
    deviceType: 'npu' // или 'gpu', 'cpu'
});
```

### 1.3. NPU: ключевое преимущество WebNN

Ключевое отличие WebNN от WebGPU — доступ к **NPU (Neural Processing Unit)**, специализированному чипу для выполнения ИИ-нагрузок .

Сравнение NPU и GPU для ИИ-задач :

| Характеристика | GPU | NPU |
|---------------|-----|-----|
| **Архитектура** | Универсальные ядра для графики | Специализированные ядра для нейросетей |
| **Энергопотребление** | Высокое (десятки ватт) | Низкое (единицы ватт) |
| **Эффективность для INT8** | Умеренная | Оптимальная (5-10x лучше GPU) |
| **Типичные задачи** | 3D-графика, GPGPU | Инференс нейросетей |

### 1.4. MLTensor API: обмен буферами с WebGPU

Одно из важнейших нововведений WebNN в 2026 году — **MLTensor API**, который позволяет разделять буферы памяти между WebNN и WebGPU . Это критически важно для приложений, которые используют WebGPU для предобработки изображений и WebNN для запуска нейросетей, без копирования данных между GPU и CPU:

```javascript
// Создание тензора WebGPU
const tensor = await context.createTensor({
    dataType: 'float32',
    dimensions: [1, 3, 224, 224]
});

// Использование этого же буфера в WebNN
// (MLTensor разделяет память с WebGPU)
const outputs = await context.compute(graph, { input: tensor });
```

Это устраняет накладные расходы на копирование данных между разными вычислительными устройствами и делает пайплайны обработки в реальном времени значительно более эффективными.

## 2. Запуск моделей (ONNX, TensorFlow Lite)

WebNN — это низкоуровневый API, ориентированный на выполнение нейросетевых операций . Он не предоставляет встроенных средств для загрузки и парсинга моделей. Разработчик обязан использовать специализированные библиотеки (ONNX Runtime Web, LiteRT/TensorFlow Lite) или загружать веса и строить граф вручную .

### 2.1. Поддерживаемые форматы моделей в 2026 году

Благодаря экосистеме инструментов, WebNN поддерживает все популярные форматы моделей:

- **ONNX (Open Neural Network Exchange).** Основной формат, поддерживаемый ONNX Runtime Web с использованием WebNN Execution Provider.
- **TensorFlow Lite (TFLite).** Поддерживается через LiteRT (библиотеку, ранее известную как TensorFlow Lite Web) .
- **Другие форматы через конвертеры.** Модели из PyTorch, Keras и других фреймворков конвертируются в ONNX или TFLite.

### 2.2. ONNX Runtime Web с WebNN

Наиболее распространенный способ запуска моделей в 2026 году — использование ONNX Runtime Web с WebNN в качестве бэкенда :

```javascript
import * as ort from 'onnxruntime-web';

// Создание сессии с WebNN
const session = await ort.InferenceSession.create('model.onnx', {
    executionProviders: ['webnn']
});

// Выполнение инференса
const feeds = { 'input': new ort.Tensor('float32', inputData, [1, 3, 224, 224]) };
const results = await session.run(feeds);
```

### 2.3. Model2WebNN: конвертер моделей в нативный код WebNN

В 2026 году появился инструмент **Model2WebNN**, который конвертирует модели ONNX и TensorFlow Lite непосредственно в JavaScript-код, использующий чистый WebNN API (без зависимости от ONNX Runtime) .

```bash
npx model2webnn model.onnx -o dist/ -d batch_size=1
```

Сгенерированные файлы :

- **`model.js`** — функция `buildGraph(context, weights)`, содержащая вызовы WebNN API.
- **`model.weights`** — бинарный файл с весами в формате WGWT (WebNN Graph WeighTs).
- **`model.manifest.json`** — индекс тензоров с их типами, формами и смещениями в бинарном файле.

Этот подход позволяет отказаться от тяжелых библиотек (ONNX Runtime) и уменьшить размер бандла.

### 2.4. Операторы, поддерживаемые WebNN

Спецификация WebNN 2026 года определяет широкий набор операторов, покрывающих большинство современных нейросетевых архитектур . Третья волна операторов добавила поддержку трансформеров, включая `dequantizeLinear`, `quantizeLinear` и attention-операции .

**Поддерживаемые операторы в 2026 году (114 операторов ONNX, 96 операторов TFLite)** :

- **Базовые:** `Add`, `Mul`, `Sub`, `Div`, `MatMul`, `Concat`, `Reshape`, `Transpose`, `Slice`, `Split`.
- **Активации:** `Relu`, `Sigmoid`, `Tanh`, `Gelu`, `HardSigmoid`, `LeakyRelu`.
- **Свертки:** `Conv`, `ConvTranspose`, `DepthwiseConv`, `AveragePool`, `MaxPool`.
- **Нормализация:** `BatchNormalization`, `LayerNormalization`, `InstanceNormalization`.
- **RNN/LSTM:** `LSTM`, `GRU` (с поддержкой сложных recurrent-архитектур).
- **Трансформеры:** `MultiHeadAttention`, `RotaryEmbedding`, `GroupQueryAttention`.
- **Квантование:** `QuantizeLinear`, `DequantizeLinear`.

### 2.5. Dead Ops и редукция графа

Model2WebNN и ONNX Runtime Web реализуют механизм **Dead Ops** (мертвые операторы) . Если модель содержит оператор, не поддерживаемый WebNN (например, `TopK` или `Range`), конвертер автоматически:

1. Отмечает выходы этого оператора как "мертвые" (dead).
2. Распространяет статус "dead" через все зависимые операции.
3. Экспортирует последние "живые" (live) выходы до зоны мертвых операторов, отбрасывая все, что находится за ней.

**Результат:** граф всегда успешно собирается, не поддерживаемые операторы просто исключаются из выполнения. Это важный механизм толерантности к неполной поддержке операторов в разных браузерах.

## 3. Сценарии использования WebNN в 2026 году

Спецификация WebNN описывает десятки прикладных сценариев, использующих аппаратно-ускоренный инференс в браузере .

### 3.1. Ресайз изображений (Super Resolution)

При низком разрешении видеопотока из-за сетевой перегрузки WebNN может запускать модель супер-разрешения (например, SRGAN) для повышения качества . В 2026 году такие модели выполняются на NPU в реальном времени, потребляя минимальную энергию.

```javascript
// Запуск super-resolution через ONNX Runtime Web
const session = await ort.InferenceSession.create('superres.onnx', {
    executionProviders: ['webnn']
});

const inputTensor = new ort.Tensor('float32', lowResImageData, [1, 3, 480, 640]);
const result = await session.run({ 'input': inputTensor });
const highResImage = result.output.data;
```

### 3.2. Удаление шума из аудио (Noise Suppression)

WebNN позволяет выполнять подавление шума в реальном времени (RNNoise, Whisper-based denoising) полностью на клиентской стороне .

Ключевое преимущество: **все данные остаются на устройстве пользователя** . Это критически важно для конфиденциальных разговоров и соблюдения регуляторных требований (GDPR, HIPAA) :

- В аудио- и видеоконференциях для подавления фонового шума.
- В системах распознавания речи для очистки аудиопотока перед транскрипцией.
- В приложениях для людей с нарушениями слуха (чистая речь для слуховых аппаратов).

### 3.3. Перевод речи в реальном времени (Speech Recognition)

Самый впечатляющий сценарий 2026 года — выполнение моделей распознавания речи (например, Whisper) на NPU в реальном времени .

**Производительность в 2026 году:** по данным разработчиков, Whisper транскрипция на NPU Snapdragon X Elite работает со скоростью **30x realtime** (в 30 раз быстрее, чем длится аудио) . Это означает, что 1 минута аудио транскрибируется за 2 секунды, с сохранением батареи устройства.

**Пример: полный воркфлоу в браузере** (источник: технический пост от разработчиков в 2026) :

```
VAD (AudioWorklet + WASM) → ASR (WebNN на NPU) → LLM (WebGPU)
→ TTS (WebNN на NPU) обратно
```

Весь пайплайн выполняется локально, без отправки данных на сервер.

```javascript
// Распознавание речи через WebNN
const session = await ort.InferenceSession.create('whisper-base.onnx', {
    executionProviders: ['webnn']
});

// Аудио с микрофона → спектрограмма → инференс → текст
const audioData = await getMicrophoneAudio();
const melSpectrogram = preprocessAudio(audioData);

const result = await session.run({ 'mel': melSpectrogram });
const transcript = postprocessText(result.output);
```

### 3.4. Другие сценарии, специфицированные W3C в 2026 году

Спецификация WebNN описывает следующие актуальные сценарии, работающие в 2026 году через WebNN с аппаратным ускорением :

- **Обнаружение лиц (Face Detection).** В системах видеонаблюдения и конференц-связи.
- **Семантическая сегментация (Semantic Segmentation).** Удаление или размытие фона в онлайн-встречах для приватности .
- **Детекция скелета (Skeleton Detection).** Распознавание жестов и языка тела .
- **Распознавание лиц (Face Recognition).** Аутентификация и проверка присутствия .
- **Обнаружение эмоций (Emotion Analysis).** Анализ настроений в чатах и видео .
- **Машинный перевод (Machine Translation).** Мгновенный перевод текста в реальном времени .

## 4. Безопасность и приватность

WebNN включает механизмы защиты от угроз, связанных с выполнением нейросетевых моделей:

- **Изоляция модели.** Модели выполняются в изолированной среде браузера, без доступа к файловой системе или другим сайтам.
- **Фингерпринтинг.** Спецификация WebNN 2026 года включает средства защиты от создания цифровых отпечатков устройства через измерение производительности модели, в частности, **coarse-grained (грубое) возвращение временных значений** .
- **Локальное выполнение.** Модели выполняются на устройстве пользователя без отправки данных в облако. Это сохраняет приватность данных (аудио, видео, текст) и позволяет использовать ИИ в офлайн-режиме .

## Итог

WebNN (Web Neural Network API) — это стандарт 2026 года, который превращает браузер в платформу для аппаратно-ускоренного выполнения нейросетевых моделей. API предоставляет доступ к CPU, GPU и NPU через унифицированный интерфейс.

- **Аппаратное ускорение.** NPU обеспечивает выполнение ИИ-моделей с низким энергопотреблением и высокой производительностью .
- **MLTensor API.** Позволяет разделять буферы памяти с WebGPU, устраняя издержки на копирование данных .
- **Поддержка форматов.** WebNN работает с ONNX и TensorFlow Lite через ONNX Runtime Web, а также через прямую конвертацию моделей в нативный код WebNN (Model2WebNN) .
- **Ключевые сценарии.** Супер-резолюция изображений, удаление шума из аудио, распознавание речи в реальном времени (Whisper на NPU — 30x realtime) .

WebNN пока находится на стадии Origin Trial в Chromium и экспериментальной поддержке в Firefox. Но его траектория ясна: к 2027 году он станет стандартным способом выполнения ИИ-нагрузок в браузере, делая веб-приложения конкурентоспособными с нативными ИИ-решениями.
