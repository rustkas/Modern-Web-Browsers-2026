# **Приложения Б** 

Это не просто алфавитный список, а **концептуальный словарь**, сгруппированный по стекам технологий. Это поможет читателю быстро ориентироваться в терминах, встречающихся в книге.

---

## Приложение В: Глоссарий терминов
### Словарь ключевых понятий современного браузерного движка

---

#### РАЗДЕЛ 1. АРХИТЕКТУРА И ЖИЗНЕННЫЙ ЦИКЛ

**Browser Process (Главный процесс)** — Управляет интерфейсом браузера (вкладки, адресная строка), координирует работу всех остальных процессов и обрабатывает права доступа.

**Renderer Process (Процесс рендеринга)** — Изолированный процесс, в котором выполняется вся логика конкретной вкладки (HTML, CSS, JavaScript). Современные браузеры используют один процесс на сайт (Site Isolation) для повышения безопасности.

**GPU Process (Процесс графического ускорителя)** — Отдельный процесс, отвечающий за отрисовку текстур, обработку WebGL/WebGPU и композитинг. Разгрузка GPU в отдельный процесс позволяет избежать зависаний интерфейса.

**Network Process (Сетевой процесс)** — Управляет всеми сетевыми запросами. Работает с кешем, прокси и HTTP/3, обеспечивая выполнение запросов независимо от жизненного цикла вкладки.

**Site Isolation (Изоляция сайтов)** — Архитектурный принцип, при котором каждый сайт (домен) запускается в своем Renderer Process. Критичен для защиты от атак Spectre и Meltdown.

**Event Loop (Цикл событий)** — Бесконечный цикл, который читает очереди задач (Task Queue) и микрозадач (Microtask Queue). Определяет порядок выполнения асинхронного кода в JavaScript.

**Task Queue (Очередь задач)** — Хранит макрозадачи: события кликов, таймауты (`setTimeout`), сетевые запросы. Выполняются по одной за итерацию Event Loop.

**Microtask Queue (Очередь микрозадач)** — Хранит промисы (`Promise.then()`, `MutationObserver`). Выполняется **сразу после** текущей макрозадачи, но **перед** рендерингом. Имеет более высокий приоритет.

**Garbage Collector (Сборщик мусора)** — Механизм автоматического освобождения памяти в движке V8 (и других). Использует алгоритмы поколенческой сборки (Generation GC) для эффективного управления объектами.

**Oilpan (Масляный бак)** — Сборщик мусора на основе трассировки (tracing GC), интегрированный в движок Blink. Управляет памятью DOM-объектов, которые не видны движку V8.

#### РАЗДЕЛ 2. РЕНДЕРИНГ И КОМПОЗИЦИЯ

**DOM (Document Object Model)** — Объектное представление HTML-документа в виде дерева узлов. Является входной точкой для всех манипуляций с содержимым страницы.

**CSSOM (CSS Object Model)** — Объектное представление стилей. Вместе с DOM образует Render Tree, на основе которого вычисляется макет.

**Render Tree (Дерево рендеринга)** — Структура, объединяющая видимые элементы DOM и их стили из CSSOM. Используется для расчета геометрии страницы. Элементы с `display: none` исключаются.

**Layout (Верстка / Reflow)** — Этап, на котором браузер рассчитывает геометрические размеры и позиции каждого элемента (ширину, высоту, координаты). Самый ресурсоемкий этап рендеринга.

**Paint (Отрисовка / Рекординг)** — Этап, на котором браузер заполняет пиксели цветами, рисует тени, градиенты и рамки. Результат — растровые изображения (битмапы) для каждого слоя.

**Rasterization (Растеризация)** — Процесс преобразования векторных данных (текст, пути SVG) в пиксели (битмапы). В современных браузерах выполняется на GPU.

**Compositing (Композитинг)** — Финальный этап, на котором браузер накладывает друг на друга предварительно отрендеренные растровые слои (например, слой с видео и слой с меню) и выводит их на экран. Выполняется исключительно на GPU.

**Layer (Слой композитинга)** — Независимая текстура в памяти GPU, которая может перемещаться, масштабироваться и становиться прозрачной без перерисовки всей страницы. Создается для элементов с `will-change`, `transform`, `opacity`, видео, canvas.

**Tiling (Тайлинг)** — Разбиение огромных страниц на квадратные "плитки" (тайлы) для рендеринга. Позволяет браузеру рендерить только видимую область (viewport) и экономить память GPU.

**Rendering Pipeline (Пайплайн рендеринга)** — Последовательность этапов: `JavaScript -> Style -> Layout -> Paint -> Composite`. Понимание этого пайплайна критично для оптимизации производительности.

**GPU (Graphics Processing Unit)** — Графический процессор. Браузер использует его для композитинга, WebGL/WebGPU вычислений и обработки CSS-эффектов (фильтры, блюр).

#### РАЗДЕЛ 3. СЕТЬ И БЕЗОПАСНОСТЬ

**CORS (Cross-Origin Resource Sharing)** — Механизм, позволяющий серверу разрешать браузеру делать запросы к ресурсам с другого домена, используя специальные HTTP-заголовки.

**HTTP/3** — Третья версия протокола HTTP, работающая поверх QUIC (UDP). Обеспечивает мультиплексирование без блокировки потоков (Head-of-Line Blocking) и 0-RTT соединения для мгновенной загрузки.

**QUIC (Quick UDP Internet Connections)** — Транспортный протокол от Google, основанный на UDP. Встроен в HTTP/3, снижает задержки соединения и улучшает производительность в условиях плохого сигнала.

**Preload / Preconnect / Prefetch** — Механизмы подсказок браузеру:
- **Preconnect:** заранее устанавливает соединение (DNS, TLS).
- **Prefetch:** загружает ресурсы для будущей навигации.
- **Preload:** срочно загружает текущий критический ресурс.

**CSRF (Cross-Site Request Forgery)** — Атака, при которой злоумышленник заставляет пользователя отправить запрос от его имени (без его ведома). Защита реализуется через токены или `SameSite` cookies.

**XSS (Cross-Site Scripting)** — Внедрение вредоносных скриптов на страницу. Защита достигается использованием Content Security Policy (CSP) и санитизацией пользовательского ввода.

**CSP (Content Security Policy)** — Заголовок безопасности, который сообщает браузеру, откуда разрешено загружать скрипты, стили, изображения (белые списки доменов).

**SRI (Subresource Integrity)** — Проверка целостности загружаемых ресурсов (скриптов, стилей) по их хешу. Гарантирует, что CDN не подменил файл на вредоносный.

**SameSite Cookies** — Атрибут кук, определяющий, когда они отправляются серверу. `SameSite=Lax` (по умолчанию) защищает от CSRF, `Strict` — полностью ограничивает передачу между сайтами.

#### РАЗДЕЛ 4. ВЫПОЛНЕНИЕ КОДА (ДВИЖКИ)

**V8 (движок)** — JavaScript и WebAssembly движок, разработанный Google для Chrome и Node.js. Написан на C++.

**SpiderMonkey** — Движок JavaScript от Mozilla Firefox. Самый первый движок JS в истории.

**JavaScriptCore (JSC)** — Движок, используемый в Safari (WebKit).

**JIT Compiler (Just-In-Time)** — Технология компиляции, при которой JavaScript транслируется в машинный код **во время выполнения**. Движки (V8, JSC) используют JIT для достижения высокой производительности.

**TurboFan** — Оптимизирующий компилятор в V8. Отвечает за генерацию высокопроизводительного машинного кода для горячих функций (которые вызываются часто).

**Ignition** — Интерпретатор байт-кода в V8. Выполняет начальную компиляцию JS, генерируя байт-код, который затем может быть оптимизирован TurboFan'ом.

**WASI (WebAssembly System Interface)** — Стандартизированный системный интерфейс для WebAssembly. Позволяет WASM-модулям получать доступ к файловой системе, сети и другим ресурсам ОС безопасным образом (выход из песочницы браузера).

#### РАЗДЕЛ 5. ОПТИМИЗАЦИЯ И МЕТРИКИ

**Core Web Vitals** — Набор ключевых метрик, определяющих качество пользовательского опыта:
- **LCP (Largest Contentful Paint):** время загрузки самого большого элемента контента (изображение, текст).
- **INP (Interaction to Next Paint):** задержка реакции на взаимодействие (клик, тап). Пришла на смену FID в 2024 году.
- **CLS (Cumulative Layout Shift):** визуальная стабильность (неожиданные смещения элементов).

**FP (First Paint)** — Время появления первого пикселя на экране (до загрузки основного контента).

**FCP (First Contentful Paint)** — Время появления первого текста или изображения.

**TTI (Time to Interactive)** — Время, когда страница становится полностью интерактивной и готова к взаимодействию с пользователем.

**INP (Interaction to Next Paint)** — Метрика, измеряющая задержку между действием пользователя (клик, тап) и отображением следующего кадра. Считается критической в 2026 году.

**Backpressure (Противодавление)** — Механизм в Streams API, при котором медленный потребитель данных сигнализирует быстрому поставщику остановиться, чтобы не переполнить память.

**Code Splitting (Разбивка кода)** — Техника, при которой бандл JavaScript разбивается на мелкие чанки (фрагменты), загружаемые только при необходимости (ленивая загрузка).

**Lazy Loading (Ленивая загрузка)** — Отложенная загрузка ресурсов (изображений, скриптов) до момента, когда они действительно понадобятся (появление в зоне видимости).

#### РАЗДЕЛ 6. ИНСТРУМЕНТЫ РАЗРАБОТЧИКА

**DevTools (Инструменты разработчика)** — Встроенный в браузер набор панелей для отладки, профилирования и анализа веб-страниц (Elements, Console, Sources, Performance, Network, Memory).

**Recorder (Панель записи)** — Инструмент в DevTools, позволяющий записывать действия пользователя на странице и преобразовывать их в тесты, скрипты для автоматизации или отладочные сниппеты.

**Performance Panel (Панель производительности)** — Инструмент для записи и анализа флейм-чартов выполнения кода, рендеринга, работы GPU и сборки мусора.

**Memory Panel (Панель памяти)** — Инструмент для снятия снимков памяти (Heap Snapshots), анализа утечек, сравнения объектов и работы со сборщиком мусора.

**Source Maps (Карты исходного кода)** — Файлы, связывающие сжатый/транспилированный код (например, из TypeScript, React) с исходными файлами, позволяющие отлаживать "родной" код в браузере.

**Origin Trials (Испытания в браузере)** — Механизм, позволяющий разработчикам тестировать новые экспериментальные API на реальных пользователях без необходимости включения флагов в `chrome://flags`. Эксперименты ограничены по времени.
